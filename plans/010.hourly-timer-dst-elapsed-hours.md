# 010 — Hourly timer skips an entry at the autumn DST change — plan

## Solution

In `TimerStrategy.processBar`, when `hodlHourly` is set, advance `next` by
`hodlDay * 3600000` ms. The daily branch (`setDate`) is unchanged. JIT tier 0:
a one-line change inside an existing method, no extraction needed.

## Build order

1. backtester: fix + test + version 1.15.1 + CHANGELOG.
2. After it is pushed: bump the `@gainium/backtester` lock pin in main-app
   (server-side backtest) and main-dash-redesign (browser backtest) to the
   same commit, so server and client results stay identical (Danger List #13).

## Blast Radius

1. Call sites: `processBar` is the only `hodlHourly` reader in the engine
   (`grep -rn hodlHourly src`). Hedge/combo reuse the DCA strategy factory.
2. No `core/` submodule in this repo.
3. Result/input types unchanged. Engine output changes only for hourly
   timers whose window crosses an autumn DST change in the running timezone
   (one extra entry per transition). Zones without DST: unchanged.
4. Existing tests on the path: `single-position*.spec.ts` and
   `futures-equity-open-deals.spec.ts` use hourly timers; the full suite with
   `TZ=Asia/Shanghai` (the golden fixtures' reference zone) is 395/395 green.
