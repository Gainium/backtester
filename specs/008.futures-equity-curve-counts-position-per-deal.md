# 008 — futures DCA equity curve counts the position's PnL once per open deal

Bug spec (Part 0 / bug template).

## §1 Definition

The equity curve (`portfolio`) of a DCA/combo backtest is the wallet balance
plus the unrealized PnL of the deals open at that moment. "Max equity drawdown"
(`maxDrawDownEquityUsd/Perc`) is read off that curve by `checkEquityDrawdown`.

- **Expected:** on a futures bot, at every curve point,
  `equity = wallet balance + Σ (each open deal's own unrealized PnL)` — the same
  per-deal valuation spot bots use and the `unrealizedPnL` stat already uses.
  At the last bar that is `initialBalanceUsd + netProfitTotalUsd + unrealizedPnLUsd`.
- **Actual:** `checkPortfolio`'s futures branch loops over the open deals and on
  every iteration adds the PnL of the whole per-symbol position. With N open
  deals the open loss is counted N times. On top of that the position's entry
  is a running blend: when a deal closes, the position shrinks but keeps the
  blended entry, so it drifts away from the remaining deals' real entries. The
  curve swings by hundreds of dollars, goes negative on a 1x bot, and the
  equity drawdown reads far beyond what the bot can lose.

§1.1 Out of scope: the position itself (it still drives liquidation), spot and
combo valuation (unchanged code path), the `unrealizedPnL` stat.

## §2 Evidence

- A reported 1-year 1m ADAUSDT USDⓈ-M run (1x, ~$5.8 deals, start $579.53):
  last curve point $736.43 at the last bar, while start + closed profit + open
  PnL = 579.53 + 37.86 − 61.92 = $555.47; curve min −$792; equity DD −$1,633.
- Runtime probe on the engine (test fixture, LONG, 1x): at 57 open deals the
  position qty equals the deals' qty (481), but position entry 0.5455 vs the
  deals' own entry 0.6716; position PnL −82.05, added ×57 = −4,676.62, while the
  deals' own PnL sums to −142.68.

## §3 Assumption (hypothesis, confirmed by §2 probe)

The ×N loop and the blended entry are the cause. Valuing each open deal from its
own fills (the existing spot loop) removes both.
