# 009 — linear futures grid: percentage stop fires late, force close pays no fee

Bug spec (Part 0 / bug template).

## §1 Definition

A futures grid bot with a percentage take profit / stop loss
(`tpSlCondition` / `slCondition` = `valueChanged`) compares
`(realized grid profit + open position value) / (initial value / leverage)`
against `tpPerc` / `slPerc` in `Strategy.tpSl()`. When it fires with
`stopAndSell`, `Strategy.closeBot()` closes the position at market.

### §1.1 The trigger values the open position on the same basis as the close

- **Expected:** on a linear (USDⓈ-M) bot the open position is worth
  `qty * (price - entryPrice)` — exactly what `closeBot` books when it closes at
  `price`. The stop fires when the result the close would realize crosses the
  threshold.
- **Actual:** the trigger used `qty * (price - entryPrice) / entryPrice * price`,
  i.e. the real value scaled by `price / entryPrice`. A long's loss was
  understated (the stop fired late), a short's overstated (it fired early). A
  reported 1x BTCUSDT run with a −5% stop saw −5.04% at the trigger and booked
  −5.84% on the close; at the corrected valuation it would have stopped about
  1,100 USDT higher.

The live bot engine already values the position as `qty * (price - entry)`.

### §1.2 The force close pays the exit fee

- **Expected:** the close is a market order and pays `userFee` on its notional,
  like every grid fill (`qty * price * fee` in quote; `qty * fee` on coin-m).
- **Actual:** the futures branch of `closeBot` booked the raw price difference
  only, so every `stopAndSell` result was better than live by one fee.

### §1.3 Out of scope

- Coin-m valuation in the trigger (unchanged; its units are a separate question).
- Slippage: grid backtests do not model slippage on any fill; adding it is a
  feature, not this fix.
- Intra-bar order of the checks (close, low, high) and filling at the checked
  candle price rather than the threshold — unchanged.

## §2 Test

`test/grid-futures-percent-sl.spec.ts` — a long building on a steady 1m decline
through a neutral linear grid with a −5% stop. Before: stops at −5.66% and the
close row carries no fee (both assertions fail). After: stops within one step of
−5% and the close row equals `qty * (exit - entry) - qty * exit * fee`.
