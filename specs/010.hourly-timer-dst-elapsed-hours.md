# 010 — Hourly timer skips an entry at the autumn DST change

Bug spec (Definition / Evidence / Assumption).

## §1 Definition

A DCA bot with the Timer start condition and `hodlHourly: true` repeats every
`hodlDay` hours.

- **§1.1 Expected:** one entry every `hodlDay` **elapsed** hours, the same
  way the live bot schedules it (main-app `dcaHelper.updateNextBuy` adds
  `hodlDay * 3600000` ms). Across the autumn DST change that still means one
  entry per elapsed hour.
- **§1.2 Actual:** in a timezone with DST, the backtest skips the repeated
  local hour. Europe/Berlin, 1h candles from 2026-10-24T22:00Z: entries at
  22, 23, 00, **02**, 03… UTC. 01:00Z (the second 02:00 local) gets none.
- **§1.3 Unchanged:** a daily timer (`hodlHourly` false) keeps firing at the
  chosen local clock time (`hodlAt`) on each local calendar day, including
  across the 25-hour day. Daily statistics keep using the local calendar.

## §2 Evidence

- Reproduced with the real engine, `test/timer-hourly-dst.spec.ts` §2.1:
  7 entries instead of 8, with `2026-10-25T01:00:00Z` missing.
- Code path: `src/dca/strategy/timer.ts` `processBar` advances `next` with
  `date.setHours(date.getHours() + hodlDay)`. From 02:00 CEST (00:00Z),
  `setHours(3)` resolves 03:00 local, which is already CET, so 02:00Z.

## §3 Assumption (root cause)

`setHours` steps the local clock label, not elapsed time; at the autumn
transition the local hour 02:00 occurs twice and the label step jumps over
the second one. Using elapsed milliseconds removes the skip. Introduced in
`451d0bb` (2023-09-20, "time in hours"); latent since.

## §4 Out of scope

- The daily branch, the initial `hodlAt` resolution, and the requested-vs-host
  timezone offset (`getTimezoneOffset`) — not reachable with a mismatch in
  the product.
- `processTrade` (trade-level path) ignores `hodlHourly` entirely; separate.
- Golden fixtures that depend on the host timezone (separate test-harness
  issue).
