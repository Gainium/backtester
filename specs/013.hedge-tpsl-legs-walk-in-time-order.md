# 013 — Hedge TP/SL: a leg's deals close before they open

Bug spec (Definition / Evidence / Assumption).

## §1 Definition

With the hedge take profit or stop loss on, `HedgeBacktesting.test()` walks
both legs bar by bar through one combined array so it can judge the shared
TP/SL after every bar.

- **§1.1 Expected:** each leg's `processBar` sees that leg's bars in time
  order, so no deal closes before it opens and no deal fills more safety
  orders than the bot allows. This holds when the legs walk different
  timeframes, for example long at 1h with an RSI on 2h and short at 15m
  with an RSI on 15m.
- **§1.2 Expected:** the same holds when both legs walk the same timeframe
  but warm up their indicators over a different number of bars.
- **§1.3 Expected:** every bar of each leg's smallest timeframe is processed
  exactly once.
- **Actual:** the legs' bars are processed out of time order. Deals show an
  end before their start, 0h duration, and more DCA orders filled than the
  maximum ("5 / 4").

## §2 Evidence

- Reporter's bot read from prod (read-only GraphQL): long leg RSI(7) 2h only,
  short leg RSI(7) 15m crosses plus RSI(7) 2h, hedge TP 1.2%, V2 base
  timeframe 1h. The smallest timeframe is 1h for the long leg and 15m for
  the short leg.
- Replay of that shape (`test/hedge-tpsl-bar-order.spec.ts`) on 1.28.0: the
  short leg's `processBar` goes back in time 366 times (§1.1) and 22 times
  with equal timeframes but different warm-up (§1.2). Every short-leg deal
  closes before it opens, and long deals show `levels.complete 5 / max 4`.
  This matches the report.
- No prod log exists for this path: the hedge backtest runs only in the
  browser (V2).

## §3 Assumption (root cause)

The combined array was built by pairing the i-th bar of each leg's smallest
timeframe and inserting both into a `Map` keyed by time. Map iteration
follows insertion order, not key order. When the i-th bars are different
moments, keys are inserted out of time order:

- The legs walk different timeframes. This has been the case since the
  combined loop was written.
- The legs start at different warm-up depths. Since c8e1a79 each leg keeps
  its own `countBack` warm-up.

A bar whose time key the other leg created early is then processed early.

## §4 Blast radius

- `src/hedge/index.ts`, shared TP/SL branch only. The TP/SL-off branch runs
  each leg's own `test()` and is unchanged.
- Host: main-dash-redesign runs hedge backtests client-side. main-app does
  not import the hedge module.
